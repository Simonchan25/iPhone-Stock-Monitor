# 已知限制与验证边界

下述 HTTP 541 故障记录来自截至 2026-10-29 的澳洲配置历史验证，不是美国配置的实时健康报告。2026-11-20 的 v1.5.2 已切换为美国 53704、Night Sky 256GB；单次查询成功不代表长期稳定。

## 未解决：Apple HTTP 541

原故障基线为 v1.5.1。真实运行反复遇到 Apple 库存接口 HTTP 541，导致库存未知和监控盲区。降低轮询频率、持久化请求预算及冷却均没有证明能消除该问题。

- 历史正式程序曾连续成功 31 次后再次受拒。
- 采用约 150 秒间隔、每滚动小时最多 24 次，仍出现相同中断。
- 隔离的 WKWebView 候选连续成功 23 次后再次 HTTP 541；一次正常会话清理和重建后仍返回 541。
- 该候选未替换正式程序，当前版本沿用正式查询实现，仅切换美国目标配置并防止恢复旧配置库存，不把失败候选描述为修复。

这些是当时的观测，不是 Apple 官方公布的额度，也不足以确定完整限制机制。15 分钟冷却是本程序策略，并非 Apple 承诺的恢复期限。没有已验证的连续监控或秒级发现保证。

## 状态与提醒的含义

| 状态或结果 | 能说明什么 |
| --- | --- |
| 正确 SKU、完整目标门店、明确可自提响应 | 在该次响应中发现相应门店可自提；以官网下单时结果为准 |
| HTTP 541、其他查询错误、缺店、错误 SKU、无法识别状态 | 本次查询失败，当前库存未知；不等于无货 |
| Bark HTTP 200 且业务代码 200 | Bark 服务接受请求；不是手机送达或有声回执 |
| 手机收到测试且有声音 | 该次通知链路有效；不是实际补货，也不保证未来送达时延 |
| 离线自测通过 | 对合成输入的解析、提醒变化、调度与请求构造符合测试；不证明线上服务稳定 |

## 其他实现边界

- 商品、地区、邮编、门店及界面文案硬编码；不是通用配置工具。
- 响应解析要求完整十二家目标门店、准确 SKU 及已知自提状态，否则报错。
- 库存变化去重只保存在进程内；重启后已有库存可能再次提醒。
- 暂停状态不是跨进程持久化开关；需要长期停用时运行停止脚本。
- Mac 休眠、关机、断网和退出登录期间无法查询。Mac 静音可能听不到本机提示音。
- Bark 强提醒需手机授权；服务器接受不等于送达。当前客户端不支持自建 Bark 服务器或端到端内容加密。
- `--check-once` 是开发诊断入口，直接发起单次查询，不共享 GUI 的持久化调度门控；不要用它规避冷却或并行运行轮询。
- 当前源码在 Apple Silicon 编译验证；未验证 Intel 实机或所有受支持 macOS 版本。

## 仓库整理验证

整理上传时应重新构建并运行 `./scripts/test.sh`，验证 App 的 plist 和临时签名，并检查待提交文件不包含真实 Bark 设备密钥、Cookie、运行日志及本地运行配置。此步骤不应触发实际库存查询或向手机发送测试通知。
